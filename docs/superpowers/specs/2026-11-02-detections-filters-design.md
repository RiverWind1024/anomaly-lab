# spec 3：检测记录页筛选与分页

> 状态：已定稿（2026-11-02）
> 前置：spec 1（连接器）、spec 2（假远端）已合入 master
> 后续：spec 4（数据保留与清理）

## 1. 目标与动机

`/detections`（检测记录页）现在把**全部**回测记录平铺在一个 280px 的窄侧栏里：

- **没有筛选** —— 上百条记录只能靠滚动找；
- **没有分页** —— 侧栏是一个 `overflow: auto` 的长列表；
- **看不出算法** —— 列表项只有 `series_id`，但记录其实是「序列 × 算法」。

同项目的评估页（`/evaluation`）已经有筛选 + 分页了，检测记录页没有 ——
**同一份数据、两套体验**。这对「作品集级可演示产品」是硬伤：
给别人看的时候，先看到的是一堵列表墙，而不是一个能用的工具。

## 2. 范围

### 做

- 检测记录页的**筛选栏**（时间范围 / 检测算法 / 形态 / 来源）+ 重置 + 计数
- 左栏列表的**分页**
- 列表项显示「序列 + 算法」，高亮按 **(序列, 算法)** 匹配
- 详情面板加头（序列 / 算法 / 形态 / F1 等）—— 让人知道在看哪条
- `/api/badcases` 支持**可选** `detector` 参数（默认 `iqr`）
- 评估页链到检测记录页时带上 `detector`

### 不做

- 平台侧 `/jobs/:id/detections` —— 那是「一次运行的结果」，不是「检测记录」，
  数据模型完全不同（runs / npz），不混在一起。
- **服务端**筛选 / 分页 —— 数据已经在客户端（见 D74）。
- 排序、批量操作、导出。

## 3. 关键事实（已核实）

| 事实 | 影响 |
|---|---|
| 记录 = **(序列 × 算法)**：`EvaluationRow` 同时有 `series_id` 与 `detector` | 列表项与高亮都要按两者 |
| `/api/summary` 已经把**全部** rows 返回前端 | 筛选在客户端做，**不需要新端点** |
| `filters.ts` 的 `filterRows` / `distinctValues` 可原样复用 | 筛选维度与评估页完全一致 |
| `/api/badcases` 的 detector **写死 `iqr`** | 筛完「检测算法」点某条，看到的却是 iqr 的结果 |
| 端点契约按**路径**比对（`{id}` 归一） | 加**可选 query 参数** → 契约守卫**不用动** |
| `make compare` 会跑多个检测器，报告 rows 里 `detector` 不止一个 | 「序列 × 算法」不是假设，是真会发生的 |

## 4. 关键设计决策

### D74：筛选与分页都在前端做

`/api/summary` 已经把全部 rows 一次性返回前端了。在后端筛要新端点 + 新契约 +
两套分页语义，纯属重复劳动。

而且评估页已经在前端筛（同一个 `filterRows`）—— **同项目、同数据、同一套筛选逻辑**
分两个地方维护是漂移的来源。

### D75：筛选维度 = `EvaluationFilters` 的五个，**不改 `filters.ts`**

时间范围 / 检测算法 / 形态 / 来源。`filterRows` 与 `distinctValues` **原样复用**。

⚠️ 不加「关键词搜索」：需求是「筛选与分页」，评估页的链接本来就能直达某条序列，
再加一个搜索框是另一个功能。

### D76：分页在左栏底部，每页 20 条

左栏是「索引」、右栏是「详情」—— master-detail。分页器属于索引那一侧。

⚠️ **分页器必须在滚动区之外**。侧栏现在是 `max-height: 70vh; overflow: auto`，
分页器放进去就要滚到底才看得见 —— 那等于没有分页。

### D77：列表项显示「序列 + 算法」，高亮按 (序列, 算法) 匹配

记录是「序列 × 算法」，只显示 `series_id` 时，同序列的不同算法分不清。

⚠️ **现在的高亮是 bug**：`row.series_id === seriesId` 会把同序列的**所有**行都点亮
（多算法回测时）。而且点哪一行看到的都是 iqr 的结果。

### D78：`/api/badcases` 加可选 `detector` 参数（默认 `iqr`）

不加的话，D77 的列表和详情对不上：筛「检测算法 = mad」，点一条，看到的还是 iqr。

⚠️ **必须校验算法名** —— 它要拼进文件路径
（`cache/detections/<detector>/<series_id>.npz`），不校验就是**路径穿越**。
用 `validate_identifier`（`^[A-Za-z_][A-Za-z0-9_]*$`）——
无点、无斜杠，且 `stl_residual` / `deseasonalized_iqr` 这类名字都合法。

向后兼容：路径不变、旧链接照常工作 → **端点契约守卫不用改**。

### D79：URL 带 `series_id` + `detector`；只有 `series_id` 时按报告解析

评估页的行本来就有 `detector`，链接补上它。

⚠️ 旧深链接（只有 `series_id`）仍要能用 —— 这时按报告里该序列的**第一条**记录解析算法。

### D80：详情面板加头 —— 序列 / 算法 / 形态 / F1

有了筛选，列表和详情可能对不上。详情头明确「我在看哪条」，消歧。

顺带把评估指标（Precision / Recall / F1）露出来 —— 这些数据本来就在 summary 行里，
右栏一直白放着。

### D81：筛选**不改变**选中项

master-detail 的常规行为：筛选只收窄左栏，右栏保持不动。

⚠️ 选中项被筛掉时，详情头要能看出来 —— 否则「筛选后 3 条，但右栏显示的不在其中」
就成了 bug 现场。做法：详情头在选中项不在当前筛选结果里时给一句提示。

## 5. 架构

```
                     /detections?series_id=X&detector=Y
                                  │
                    ┌─────────────┴─────────────┐
                    │  DetectionsPage           │
                    │  ├─ 筛选栏（5 个筛选）      │  ← filterRows / distinctValues
                    │  ├─ 左栏 DetectionsList    │  ← 分页
                    │  │   └─ 每项 (序列, 算法)    │
                    │  └─ 右栏 详情头 + 图表      │  ← /api/badcases?series_id&detector
                    └───────────────────────────┘
```

**数据流**（全部在前端闭环）：

```
/api/summary ──► rows ──► filterRows(rows, filters) ──► filtered
                    │                                      │
                    │                              分页切片 ──► 当前页 items
                    │                                      │
                    └────── resolveSelected(rows, url) ◄────┘
                                   │
                                   ▼
                    /api/badcases?series_id&detector ──► 详情
```

**深链接跳页**：URL 里的记录可能落在第 3 页 —— 选中项变化时把页码拨到它所在的那页，
否则用户看不到自己选中的东西被高亮。

## 6. 数据契约

### `GET /api/badcases?series_id=<id>&detector=<name>`

| 参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `series_id` | 是 | — | 序列 ID（必须在数据集里） |
| `detector` | 否 | `iqr` | 检测算法名 |

| 情况 | 状态码 | 说明 |
|---|---|---|
| 正常 | 200 | 返回 `detector` 字段 = 实际算法名 |
| 序列不存在 | 404 | 「序列不存在」 |
| 算法名非法（含 `/`、`.` 等） | **400** | 路径穿越防护 |
| 该算法下没有这条序列的检测结果 | 404 + `no_result` | 业务态空态（前端显示「该序列还没有检测结果」） |

⚠️ `detector` 参数**不进响应结构**，只是多一条输入 ——
响应里已经有 `detector` 字段（从 npz 读的），前端可以直接用它核对。

### 前端 URL 参数

| 参数 | 说明 |
|---|---|
| `series_id` | 选中的序列 |
| `detector` | 选中的算法（缺省时按报告解析） |

## 7. 测试策略

### 后端

| 测试 | 内容 |
|---|---|
| `detector` 生效 | `?detector=mad` 读的是 `detections/mad/` 下的 npz，不是 iqr 的 |
| 默认兼容 | 不带 `detector` → 仍然读 iqr（老行为不变） |
| 路径穿越 | `?detector=../../etc` → 400，**不是** 404/500 |
| 非法字符 | `?detector=a/b` → 400 |
| 不存在的算法 | `?detector=nope` → 404 + `no_result` 业务头 |
| 契约 | `/api/badcases` 路径不变 → 端点契约守卫仍然绿 |

### 前端

| 测试 | 内容 |
|---|---|
| 纯函数 | `resolveSelected`（有/无 detector、找不到、跨算法） |
| 纯函数 | 分页切片（首页、末页、超界） |
| 页面 | 筛选生效后列表条目数变化；分页显示「共 N 条」 |
| 页面 | 点列表项 → URL 带上 `series_id` + `detector` |
| 页面 | 高亮唯一（同序列不同算法不会同时点亮）—— D77 的 bug 守卫 |
| 回归 | 评估页链接带上 `detector`（改 `evaluation.test.tsx` 的既有断言） |

## 9. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 报告里有多个算法 → 列表项重名 | 列表项带算法标签，高亮按两者匹配（D77） |
| 深链接指向第 3 页的记录 | 选中项变化时自动拨页（D79 + 架构节） |
| 筛选后选中项不在列表里 | 详情头提示（D81） |
| `detector` 参数被用来穿越路径 | `validate_identifier` + 400（D78） |
| 前端筛选逻辑与评估页漂移 | 复用**同一个** `filterRows` / `distinctValues`（D75） |

## 10. 验收标准

1. 检测记录页有筛选栏，5 个维度都能筛，筛选后计数正确；
2. 左栏有分页，每页 20 条，可切页大小；
3. 列表项能区分算法；同一序列的不同算法不会同时高亮；
4. 点某条记录，右栏显示的是**那条记录自己的算法**的结果；
5. 评估页点序列 → 跳到检测记录页并选中那条；
6. 深链接（带 `series_id` + `detector`）能直达并高亮；
7. 后端测试全绿、`make lint` 全绿、前端测试与类型检查全绿；
8. **端点契约守卫仍然绿**（路径没变）。
